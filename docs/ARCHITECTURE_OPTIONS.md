# 可选架构：训练、向量检索、REST、数据库与权限

本页描述后续可选路线，均不是当前版本已经具备的能力。

## 1. 用论文材料微调或强化学习

把 PDF 放入论文库不会自动训练模型。微调需要成对的监督样本，例如“任务与证据 → 理想回答/正确工具轨迹”；强化学习还需要可计算的奖励、很多次任务轨迹和训练算力。只有原始论文通常不足以得到可靠行为，且涉及版权、隐私、错误反馈和灾难性遗忘风险。

推荐顺序是：先用 RAG 检索论文；再收集用户明确同意保存的纠错、评分和理想答案；建立离线评测；数据量和质量足够后，再考虑 LoRA/SFT。RL 只适合奖励可客观验证的窄任务。默认不拿用户论文或聊天训练共享模型。

## 2. 向量数据库

向量数据库本身不需要训练，它负责保存 Embedding 向量及其标题、页码等元数据，并按相似度查找。可使用开源本地方案（如 FAISS、Chroma、Qdrant）或托管服务。桌面 Demo 更适合先做本地向量索引，与现有 BM25 组成“关键词 + 语义”的混合检索。

## 3. Embedding 模型

无需从零训练。可以使用公开预训练的中英多语或科研文本 Embedding 模型，在本机运行，或调用兼容 API。只有积累了“查询—相关论文/段落”标注后，才值得微调 Embedding。自训模型需要大量正负样本、GPU 和独立评测，不应作为第一步。

## 4. REST 服务和互联网访问

可先用 FastAPI 增加只监听 `127.0.0.1` 的本地 REST 服务，供本机其他程序调用；这不等于公网服务。公网访问需要云主机或受控隧道、HTTPS、身份认证、限流、日志和密钥管理。不要直接把桌面程序或论文目录暴露到公网。

## 5. 数据库与同步

数据库不一定意味着客户端和服务器各存一份。可选三种模式：

- 本地优先：SQLite/本地向量库，只在用户电脑保存，隐私最好。
- 云端优先：服务器保存，便于网页和多设备访问，但依赖网络与账号安全。
- 混合同步：本地可离线，云端做备份和多设备同步；需要处理冲突、删除传播和加密。

网上有开源自建及免费/付费托管数据库，但套餐会变化。真正接入前再按数据地区、容量、备份、合规和价格核对官方条款。论文原文是否上传云端应由用户单独选择，不能默认同步。

## 6. 工具权限模式

可以设计三档，但“完全访问”也不应等于无限系统权限：

- 受限访问：只读当前论文库；禁用联网、下载、删除、外部程序和写文件。
- 每次询问：危险动作先显示工具名、目标、将发送的数据和影响，得到确认后执行。
- 自动执行：只对白名单工具、当前论文库/工作区和设定额度自动运行；删除、上传、付费调用、凭据访问仍保留硬性确认。

每次动作都应写审计日志，并提供立即停止。权限最好按论文库或任务保存，而不是给模型一次性授予整个电脑的无限权限。

## 推荐实施顺序

1. 本地预训练 Embedding + 向量索引，与 BM25 做混合检索和对照评测。
2. 三档工具权限、动作预览与审计日志。
3. 本机 FastAPI REST，仅监听 localhost。
4. 可选登录和云同步；默认本地优先，论文上传需单独同意。
5. 收集高质量、明确授权的反馈数据后，再评估 SFT/LoRA；最后才考虑 RL。
