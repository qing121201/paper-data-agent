# 模块契约与依赖方向

## 总体形式

项目采用模块化单体：所有功能可以在同一个桌面进程运行，但模块通过明确数据结构和服务接口协作。

```text
UI → 应用服务/Agent → 领域能力 → 基础设施
                     ↘ 输出能力
```

领域能力不得反向导入 Tk 控件；基础设施不得控制产品流程。

## UI 契约

UI 只负责收集输入、展示状态和调用服务。耗时任务必须进入后台线程，并通过 Tk 主线程回调更新界面。UI 不自己计算推荐分数、不解析 PDF、不拼装 OpenAlex 请求。

## 论文库与检索契约

输入：本地路径、公开下载结果、查询文本、阅读预算。

输出：标准化论文记录、带论文 ID/路径/页码的文本块、检索结果、阅读覆盖清单。

论文库不得依赖 GUI 或特定模型供应商。索引格式变更必须带版本或兼容读取策略。

## Agent 契约

Agent 通过白名单工具调用领域能力。规划输出不是执行权限；每个工具仍校验参数、文件范围和网络边界。最终回答必须能追溯到原始证据或明确标记为模型生成内容。

## 在线发现契约

输入：订阅主题、期刊/会议、时间范围、排序方式和数量。

输出：标准化候选论文，包括标题、作者、日期、来源、引用数、DOI、OpenAlex ID、落地页、公开全文候选和链接验证状态。

推荐只能把候选交给论文库导入接口，不直接写论文库内部 JSON 或索引。

## PPT 与可视化契约

输入：已核验的论文证据、图片资产、结构化页面规格或用户数据表。

输出：版本化规格、资产副本、可编辑 PPTX、逐页预览和质量报告。

任何原文截图必须保存来源论文和页码；自绘图必须保存输入数据和生成清单。PPT 模块不读取首页控件或推荐缓存。

## 基础设施契约

外部 HTTP、文件下载、本地模型和 PowerPoint 自动化必须封装，支持超时、错误翻译和测试替身。密钥通过配置对象传入，不写入日志、回答或版本库。

## 数据目录边界

当前开发版本仍从仓库内的 `libraries/`、`config/`、`output/` 读取已有数据。目标产品将运行时数据迁移到用户数据目录；迁移前必须：

1. 备份并识别现有论文库。
2. 支持旧目录探测或一次性复制，而不是静默移动。
3. 向用户展示新旧位置和可回滚方式。
4. 验证论文数量、元数据、索引和会话记录后才切换默认路径。
