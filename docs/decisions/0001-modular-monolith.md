# ADR-0001：采用模块化桌面单体

- 状态：已接受
- 日期：2026-09-19

## 背景

当前产品由一名用户借助多个 AI 开发任务持续迭代。功能包括本地论文库、Agent、在线发现和 PPT，但尚不需要多人服务端并发、账户系统或云同步。

## 决定

近期保持单一 Python 桌面应用，在包内部按 UI、论文库与检索、Agent、发现推荐、PPT/可视化和基础设施划分模块。开发任务与这些模块对齐，使用文档化契约协作。

## 原因

- 本地优先能力不需要网络服务间通信。
- 单体便于调试、打包和保护用户论文数据。
- 明确模块边界已经能解决大文件、职责混杂和 AI 并发修改冲突。
- 若过早拆成服务，会增加认证、部署、同步和故障处理成本。

## 后果

- 必须持续约束依赖方向，不能把所有逻辑重新堆回 GUI 或适配器。
- 并行 AI 开发需要 worktree/分支和明确文件所有权。
- 将来若增加云同步或 Web 客户端，可从稳定应用服务接口拆出本地 REST/云服务，而不先重写领域逻辑。
